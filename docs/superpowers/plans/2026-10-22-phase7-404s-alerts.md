# Phase 7: 404s Page and Alerts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. RED → GREEN per task; the named tests are the binding contract.

**Goal:** Marketers see each broken URL once, with hits, last seen and top referrer, and fix, ignore or delete it in one click. The team gets a daily or weekly email of new 404s without logging in.

**Architecture:**
- `Redirection\Alerts\Digest`:
  - `select()` is pure: it applies `min_hits`, drops already-redirected URLs (through a callable) and caps at 20.
  - `run()` queries `redirection_404` since the last send, calls `wp_mail`, and records the send time.
  - `schedule()` and `clear()` follow the `Flusher` pattern on hook `dsr_404_digest`.
- Settings `dsr_alerts` `{enabled, frequency, recipients, min_hits}` are cleaned in `Settings::apply_settings`. The digest is (re)scheduled from the existing `redirection_save_options` filter and cleared on deactivation.
- `Redirect::matches_any( $url )` is shared by the digest and `/health`, which already has the same private check.
- `Error` (404 log) adds two things:
  - Grouped-by-URL rows gain `last_seen` and `referrer` (the top referrer), from one extra query for the page's URLs.
  - Two filters: `since` (days) and `ignored` (`1` means a "do nothing" redirect exists for the URL, `0` means none does).
- The 404s page is rebuilt in `src/page/logs404` like the Redirects page:
  - chips: New this week · All · Ignored
  - search by URL
  - row actions: Fix (drawer prefilled), Ignore (creates a "do nothing" redirect), Delete
  - The old upstream table files are deleted.
- Settings gains a "404 alerts" section with its own Save. It warns when alerts are on but 404 logging is off (`expire_404 = -1`).

**Spec:** §4.5 404s, §5.3, §6 (`wp_mail` failure), §7 (`is_email`, escaping), §8 (digest cases), §9 step 7.

## Decisions
1. **`last_sent` lives in its own option, `dsr_404_digest_last_sent`** (a UTC timestamp), not inside `dsr_alerts`. Saving settings can then never reset it, and the sanitizer needs no exception.
2. **Ignore = upstream's "do nothing" redirect** for the exact URL. A matched redirect stops 404 logging (`class-plugin.php:218`), so the URL stops reappearing. The Ignored chip lists URLs that have one.
3. **The 404s page is URL-grouped only**, per the spec. Upstream's group-by-IP and group-by-agent views and its block-IP action are dropped; IP blocking stays possible through the drawer's Advanced conditions.
4. **Subject:** `[Site] N new 404s this week` (or `today` for daily), where N is the number of URLs in the email.
5. **Reschedule only when the frequency changes or alerts are switched on or off**, so saving unrelated settings doesn't move the next send.
